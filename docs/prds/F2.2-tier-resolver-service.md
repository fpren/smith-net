## 1. Problem

After F2.1 the schema can express tier state, but no service code reads it, no endpoint exposes entitlements to clients, and JWTs don't carry tier claims. Every downstream PRD (F3.x billing, F4.x UI, F6.1 enforcement, F7.1 trial) depends on this.

## 2. Goal

After this PRD:
- A `TierResolver` service is the single source of truth for "what is this user's tier and what can they do?"
- A `GET /api/me/entitlements` endpoint returns the contract per `API-SPEC.md §15`
- JWTs carry `tier` and `entitlements` claims that update on tier change
- A `requireTier(minTier)` middleware enables the F6.1 enforcement story
- The `EntitlementsRepository` is exposed to the Android client via API; client caches it locally

## 3. Non-goals

- The trial-start flow itself (F7.1)
- The cap enforcement middleware that USES requireTier (F6.1 — separate)
- Stripe / Play Billing integration (F3.x)
- The Android UI for entitlements display (F4.x)

## 4. Design

### 4.1 TierResolver service

```typescript
// backend/src/services/tierResolver.ts
import { pg } from '../db';
import { Tier, ProfileTier, Subscription } from '../types/tier';

export interface Entitlements {
  tier: Tier;
  trialing: boolean;
  trialEndsAt?: number;          // epoch ms
  founderPricingLocked: boolean;
  caps: {
    activeJobs: number | 'unlimited';
    pdfSendsPerMonth: number | 'unlimited';
    advancedTemplate: boolean;
    enterpriseTemplate: boolean;
    smithAI: boolean;
    crew: boolean;
  };
  founderSeatsRemaining: {
    solo: number;
    advanced: number;
    enterprise: number;
  };
}

const CAPS_BY_TIER: Record<Tier, Entitlements['caps']> = {
  open: {
    activeJobs: 1,
    pdfSendsPerMonth: 5,
    advancedTemplate: false,
    enterpriseTemplate: false,
    smithAI: false,
    crew: false,
  },
  solo: {
    activeJobs: 'unlimited',
    pdfSendsPerMonth: 'unlimited',
    advancedTemplate: false,
    enterpriseTemplate: false,
    smithAI: false,
    crew: false,
  },
  advanced: {
    activeJobs: 'unlimited',
    pdfSendsPerMonth: 'unlimited',
    advancedTemplate: true,
    enterpriseTemplate: false,
    smithAI: true,
    crew: false,
  },
  enterprise: {
    activeJobs: 'unlimited',
    pdfSendsPerMonth: 'unlimited',
    advancedTemplate: true,
    enterpriseTemplate: true,
    smithAI: true,
    crew: true,
  },
};

export async function resolveTier(profileId: string): Promise<Entitlements> {
  // Read profile (single source for tier; subscriptions are reconciled by F3.x)
  const { rows: profileRows } = await pg.query(
    `SELECT tier, tier_expires_at, trial_started_at, trial_tier,
            trial_cc_captured, founder_pricing_locked_at
       FROM profiles WHERE id = $1`,
    [profileId]
  );
  if (profileRows.length === 0) throw new Error('profile not found');
  const p = profileRows[0];

  // Determine tier (profiles.tier is the mirror; subscriptions row would reconcile via F3.x cron)
  const tier: Tier = p.tier;
  const trialing = p.trial_started_at != null && p.tier_expires_at != null && p.tier_expires_at > new Date();
  const trialEndsAt = p.tier_expires_at?.getTime();

  // Founder seats — fetched in parallel
  const founderSeatsRemaining = await getFounderSeatsCounts();

  return {
    tier,
    trialing,
    trialEndsAt,
    founderPricingLocked: p.founder_pricing_locked_at != null,
    caps: CAPS_BY_TIER[tier],
    founderSeatsRemaining,
  };
}

// Helper — returns counts for all 3 founder bonus types
async function getFounderSeatsCounts() {
  // Pre-F5.1: hardcoded constants from pricing-config.json. F5.1 replaces with real DB read.
  return { solo: 1000, advanced: 100, enterprise: 10 };
}
```

### 4.3 JWT tier claim

```typescript
// backend/src/auth.ts (modify generateTokens)
export function generateTokens(user: User & { tier: Tier }) {
  const accessToken = jwt.sign(
    {
      userId: user.id,
      email: user.email,
      role: user.role,
      tier: user.tier,                          // NEW
      entitlementsHash: hashEntitlements(user), // NEW — for cache-bust signaling
    },
    JWT_SECRET,
    { expiresIn: JWT_EXPIRES_IN }
  );
  // ... refresh token ...
  return { accessToken, refreshToken };
}
```

`entitlementsHash` is a short SHA256 of the resolved entitlements — clients detect tier-meaningful change via header `X-Entitlements-Hash` on responses; if mismatch with their cached hash, they refetch `/api/me/entitlements`.

### 4.4 Tier-change rolling

When a tier changes server-side (admin action, trial start, billing webhook), server should re-issue tokens. Two options:

**Option A:** push notification + client refresh on receive
**Option B:** include `X-Tier-Changed: true` response header on the next API call after a tier change; client refreshes automatically

Decision: **B (header-based)** for v1 — simpler, no FCM dependency for this flow. F6.x adds the actual emit on tier-change events.

### 4.5 `requireTier` middleware

```typescript
// backend/src/middleware/tier.ts
import { Tier } from '../types/tier';
import { Request, Response, NextFunction } from 'express';
import { AuthenticatedRequest } from '../auth';

const TIER_RANK: Record<Tier, number> = { open: 0, solo: 1, advanced: 2, enterprise: 3 };

export function requireTier(min: Tier) {
  return (req: AuthenticatedRequest, res: Response, next: NextFunction) => {
    const userTier = req.user!.tier as Tier;
    if (TIER_RANK[userTier] < TIER_RANK[min]) {
      return res.status(403).json({
        error: `Requires ${min} tier`,
        code: 'tier_gate_exceeded',
        gate_id: 'tier_minimum',
        current_tier: userTier,
        details: { target_tier: min },
      });
    }
    next();
  };
}
```

(F6.1 layers cap-specific middleware on top.)

### 4.6 Client cache (Android)

`EntitlementsRepository.kt` (new):
```kotlin
object EntitlementsRepository {
    private val _entitlements = MutableStateFlow<Entitlements?>(null)
    val entitlements: StateFlow<Entitlements?> = _entitlements

    suspend fun refresh() {
        val resp = api.getEntitlements()
        _entitlements.value = resp
    }

    suspend fun ensureFresh() {
        if (_entitlements.value == null) refresh()
    }
}
```

Called on app cold start, after login, after tier-change header detected, after WS push (F5.x adds `entitlements_changed` event).

## 7. Edge cases

| Case | Behavior |
|---|---|
| User has no `subscriptions` row but `profiles.tier='solo'` (admin manually set) | Resolver trusts profile.tier; subscription reconciler (F3.3 cron) is the auditor |
| Tier expires mid-request | Resolver checks `tier_expires_at > NOW()`; downgrade reflected immediately on next request |
| JWT carries stale tier (user upgraded; cached token) | X-Tier-Changed header forces refresh; next call uses new token |
| Founder seat counts unavailable (F5.1 not yet shipped) | Hardcoded constants from pricing-config.json — F5.1 replaces with DB read |
| Concurrent calls during tier change | Resolver re-reads from DB each call; eventual consistency acceptable |
| `requireTier('open')` (everyone passes) | Allowed; useful for endpoints that are auth-but-tier-agnostic |
