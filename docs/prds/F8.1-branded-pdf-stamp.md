# F8.1 — Branded PDF stamp (template edits)

| Field | Value |
|---|---|
| Pitch | 8 — Branded PDF stamp + send queue |
| Cycle | 3 |
| Appetite | 2 days |
| Owner | backend |
| Dependencies | F2.2 (tier resolution at send time) |
| Closes blocker | B7 |

---

## 1. Problem

Free tier needs Smith Net branding on PDFs + email signatures (passive distribution surface). Decision per `FLOW-8` edge case: stamp tier-locked at SEND time, not view time.

## 2. Goal

After this PRD: Open-tier sent PDFs have a branded footer; Solo+ tier sent PDFs do not. Same for email signature. No retroactive stamp changes after send.

### 3.3 Email signature (server-side append)

```typescript
// backend/src/services/emailService.ts (or wherever invoice send composes email body)
function composeInvoiceEmailBody(invoice: Invoice, isOpenTier: boolean): string {
  let body = renderInvoiceEmailTemplate(invoice);
  if (isOpenTier) {
    body += `\n\n--\nSent via Smith Net (smithnet.app)`;
  }
  return body;
}
```

### 3.4 Send-time tier resolution

```typescript
// backend/src/api.ts — POST /api/invoices/:id/send (already has cap check from F6.1)
apiRouter.post('/invoices/:id/send', pdfSendsCap, async (req: AuthenticatedRequest, res) => {
  const invoiceId = req.params.id;
  const profileId = req.user!.id;

  // Resolve tier AT SEND TIME (deterministic)
  const ent = await resolveTier(profileId);
  const isOpenTier = ent.tier === 'open';

  // Render PDF with isOpenTier context
  const pdfBuffer = await renderInvoicePdf(invoiceId, { isOpenTier });

  // Compose email with conditional signature
  const emailBody = composeInvoiceEmailBody(invoice, isOpenTier);

  // Send
  await emailService.send({
    to: invoice.client_email,
    subject: `Invoice from ${invoice.contractor_name}`,
    body: emailBody,
    attachments: [{ filename: 'invoice.pdf', content: pdfBuffer }],
  });

  // Record send-time tier on invoice for audit
  await pg.query(`UPDATE invoices SET sent_with_branding = $2 WHERE id = $1`, [invoiceId, isOpenTier]);

  // Increment counter (per F6.1)
  await pg.query(`UPDATE profiles SET pdf_sends_this_month = pdf_sends_this_month + 1 WHERE id = $1`, [profileId]);

  res.json({ ok: true });
});
```

## 4. Acceptance criteria

| AC | Description |
|---|---|
| AC-1 | Open user sends invoice → PDF contains "Sent via Smith Net — smithnet.app" footer | HTML snapshot |
| AC-2 | Solo+ user sends invoice → PDF does NOT contain footer | HTML snapshot |
| AC-3 | Open user email body ends with `\n--\nSent via Smith Net (smithnet.app)` | Email assertion |
| AC-4 | Solo+ user email signature unchanged from contractor's setting | Email assertion |
| AC-5 | Tier resolved at SEND time (not draft time, not view time) | Test |
| AC-6 | invoices.sent_with_branding records the decision (audit trail) | DB assertion |
| AC-7 | Tier upgrade after send does NOT alter already-sent PDF | Already-sent test |
| AC-8 | Tier downgrade between draft and send → uses tier at send time | Test |
| AC-9 | Public-page render of `/i/:uuid` re-uses sent_with_branding column (not re-resolved) | Public page test |

## 5. BDD scenarios

```gherkin
Scenario: Open user sends invoice with branding
  Given an Open-tier contractor
  When they POST /api/invoices/:id/send
  Then the rendered PDF HTML contains class="smith-net-footer"
  And contains "Sent via Smith Net — smithnet.app"
  And the email body ends with "Sent via Smith Net (smithnet.app)"
  And invoices.sent_with_branding = true

Scenario: Solo user sends invoice without branding
  Given a Solo-tier contractor
  When they POST /api/invoices/:id/send
  Then the rendered PDF does NOT contain smith-net-footer class
  And the email signature is unchanged
  And invoices.sent_with_branding = false

Scenario: Tier upgrade does not retroactively change branding
  Given a previously-sent invoice with sent_with_branding=true
  When the contractor upgrades to Solo
  And the customer views /i/:uuid
  Then the page still renders with branding (sent_with_branding column controls)

Scenario: Public page uses sent_with_branding (frozen)
  Given an invoice was sent with branding
  When GET /i/:uuid is called
  Then the page renders the smith-net-footer
  Even if contractor.tier is now "solo"
```

## 6. Edge cases

| Case | Behavior |
|---|---|
| Tier exactly on boundary at send | Server reads `profiles.tier` atomically; whichever is in DB wins |
| Send fails (SMTP error) | Counter NOT incremented; row marked `send_failed`; sent_with_branding NULL |
| Invoice already-rendered cached PDF | New tier-aware render replaces cache; cache key includes isOpenTier |
| Customer prints PDF | print CSS preserves footer (per FLOW-8 §6) |
