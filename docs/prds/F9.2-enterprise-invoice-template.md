## 1. Problem

Enterprise tier ($50/mo) hero is multi-user crew + Enterprise template. The Enterprise template needs multi-payer (split across N parties) and milestone billing (% complete) — features not in Standard or Advanced.

## 2. Goal

After this PRD: Enterprise users can split a single invoice across multiple payers with their own line items and milestone tracking.

## 3. Non-goals

- Auto-split based on rules (manual split only v1)
- Per-payer payment portals (each payer gets the same public link, just shows their share)
- Draw schedule with construction-loan integrations (deferred per Step 10 rabbit-hole notes)

## 4. Design

### 4.1 Schema additions

```sql
-- 014_invoice_enterprise_fields.sql
CREATE TABLE IF NOT EXISTS invoice_payers (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  invoice_id UUID NOT NULL REFERENCES invoices(id) ON DELETE CASCADE,
  payer_name TEXT NOT NULL,
  payer_email TEXT,
  payer_address TEXT,
  share_percent NUMERIC(5,2),  -- 0.00 to 100.00
  share_amount NUMERIC(12,2),  -- absolute amount alternative
  status TEXT NOT NULL DEFAULT 'unpaid' CHECK (status IN ('unpaid','viewed','paid')),
  paid_at TIMESTAMPTZ
);
CREATE INDEX idx_invoice_payers_invoice ON invoice_payers(invoice_id);

CREATE TABLE IF NOT EXISTS invoice_milestones (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  invoice_id UUID NOT NULL REFERENCES invoices(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  description TEXT,
  percent_complete NUMERIC(5,2) NOT NULL DEFAULT 0,
  amount NUMERIC(12,2) NOT NULL,
  due_date TIMESTAMPTZ,
  completed_at TIMESTAMPTZ,
  sort_order INTEGER DEFAULT 0
);
CREATE INDEX idx_invoice_milestones_invoice ON invoice_milestones(invoice_id);
```

### 4.3 Server tier check (extends F9.1 logic)

```typescript
if (template === 'enterprise' && TIER_RANK[ent.tier] < TIER_RANK['enterprise']) {
  return res.status(403).json({
    error: 'Enterprise template requires Enterprise tier',
    code: 'tier_gate_exceeded',
    gate_id: 'enterprise_template',
    current_tier: ent.tier,
    details: { target_tier: 'enterprise' },
  });
}
```

### 4.4 Per-payer share validation

```typescript
// In POST/PATCH invoice payers
const sumPercent = payers.reduce((s, p) => s + Number(p.share_percent || 0), 0);
const sumAmount = payers.reduce((s, p) => s + Number(p.share_amount || 0), 0);
if (sumPercent > 100.01) return res.status(400).json({ error: 'Payer shares exceed 100%' });
if (sumAmount > Number(invoice.total) + 0.01) return res.status(400).json({ error: 'Payer amounts exceed invoice total' });
```

(0.01 tolerance for rounding.)

### 4.5 Public-page per-payer view

`GET /i/:uuid?payer=:payerId` filters totals to that payer's share. Default `/i/:uuid` shows full invoice.

### 4.6 Android UI for payers + milestones (Enterprise-only)

Add two new screens accessed from H1 InvoiceScreen for Enterprise users:
- `InvoicePayersScreen` — add / edit / remove payers + percent / amount
- `InvoiceMilestonesScreen` — add / edit milestones + percent_complete + due_date

Both gated by `entitlements.caps.enterpriseTemplate`.

## 5. Acceptance criteria

| AC | Description |
|---|---|
| AC-1 | invoice_payers + invoice_milestones tables created via migration |
| AC-2 | Enterprise template renders payers table, milestones table when populated |
| AC-3 | Empty payers / milestones don't render their sections (no broken layout) |
| AC-4 | Solo / Advanced user attempting send with template='enterprise' → 403 enterprise_template |
| AC-5 | Enterprise user sends successfully |
| AC-6 | Sum of share_percent enforced ≤ 100 (with 0.01 tolerance) |
| AC-7 | Sum of share_amount enforced ≤ invoice.total |
| AC-8 | Public page `/i/:uuid?payer=X` shows only X's share |
| AC-9 | Per-payer status updates on `viewed_at` per payer (separate UUIDs OR query param tracking) |
| AC-10 | Milestone percent_complete edits supported via PATCH endpoint |
| AC-11 | Android UI for payers/milestones gated to Enterprise tier |

## 7. Edge cases

| Case | Behavior |
|---|---|
| Single payer at 100% | Renders normally; effectively standard layout with one PAYERS row |
| Milestone amounts exceed invoice total | Allowed (overhead — milestone billing is informational, not authoritative for total) |
| Payer removed after invoice sent | Soft-delete (status='canceled'); rendered PDF historical record preserved |
| Enterprise → Advanced downgrade with Enterprise-template draft | DB template field stays; send-time check rejects; user must re-pick |
