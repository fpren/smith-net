## 1. Problem

Enterprise tier hero feature is multi-user crew. Currently `organizations` exists only in legacy Supabase schema. Hetzner has no orgs concept. Need a single canonical schema for crew membership keyed to subscriptions.

## 2. Goal

After this PRD: Hetzner schema has `organizations` and `org_members` tables, populated automatically when a user upgrades to Enterprise. Crew membership becomes the authoritative source for "who can see what."

## 3. Non-goals

- The invite flow itself (F10.2)
- Shared-jobs filtering (F10.3)
- DispatchScreen UI (F10.4)
- Migration of existing legacy Supabase organizations data (no real users; skip)
- SAML / SSO crew federation (post-launch)

## 4. Design

### 4.1 Migration M10

```sql
-- 016_create_organizations_table.sql
BEGIN;

CREATE TABLE IF NOT EXISTS organizations (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  owner_profile_id TEXT NOT NULL REFERENCES profiles(id),
  subscription_id UUID REFERENCES subscriptions(id),  -- one Enterprise sub per org
  default_tax_rate NUMERIC(5,2) DEFAULT 0,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS org_members (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
  profile_id TEXT NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
  role TEXT NOT NULL DEFAULT 'member'
    CHECK (role IN ('owner', 'foreman', 'lead', 'member')),
  joined_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  removed_at TIMESTAMPTZ,
  UNIQUE (org_id, profile_id)
);

CREATE INDEX IF NOT EXISTS idx_org_members_org ON org_members(org_id) WHERE removed_at IS NULL;
CREATE INDEX IF NOT EXISTS idx_org_members_profile ON org_members(profile_id) WHERE removed_at IS NULL;

-- Add org_id to profiles for fast lookup of "user's primary org"
ALTER TABLE profiles ADD COLUMN IF NOT EXISTS org_id UUID REFERENCES organizations(id);
CREATE INDEX IF NOT EXISTS idx_profiles_org ON profiles(org_id) WHERE org_id IS NOT NULL;

COMMIT;
```

### 4.2 Auto-create org on Enterprise subscription

Modify F3.1's `handleCheckoutCompleted` (and F3.2's purchase verification) so when `targetTier === 'enterprise'`, an org is auto-created with the user as owner:

```typescript
// In webhook + verification handlers — after subscriptions row insert:
if (tier === 'enterprise') {
  await ensureOrgForUser(profileId, subscriptionId);
}

async function ensureOrgForUser(profileId: string, subscriptionId: string) {
  const { rows: existingOrg } = await pg.query(
    `SELECT id FROM organizations WHERE owner_profile_id = $1`, [profileId]
  );
  if (existingOrg.length > 0) {
    // Re-link subscription
    await pg.query(`UPDATE organizations SET subscription_id = $2 WHERE id = $1`,
                   [existingOrg[0].id, subscriptionId]);
    return existingOrg[0].id;
  }

  const { rows } = await pg.query(`
    INSERT INTO organizations (name, owner_profile_id, subscription_id)
    VALUES ($1, $2, $3) RETURNING id
  `, [
    `${(await getProfile(profileId)).display_name}'s Crew`,
    profileId, subscriptionId
  ]);
  const orgId = rows[0].id;

  // Owner auto-joins as 'owner' role
  await pg.query(`
    INSERT INTO org_members (org_id, profile_id, role) VALUES ($1, $2, 'owner')
  `, [orgId, profileId]);

  // Set primary org on profile
  await pg.query(`UPDATE profiles SET org_id = $2 WHERE id = $1`, [profileId, orgId]);

  return orgId;
}
```

### 4.3 Tier downgrade behavior

When Enterprise subscription expires:
- Org is NOT deleted (preserves data per principle)
- `subscription_id` becomes NULL
- Crew members can no longer be added (F10.2 enforcement)
- Existing crew members remain visible / read-only access (F10.3 enforcement)

### 4.4 Read endpoints

```typescript
// GET /api/me/org — current user's primary org + members
apiRouter.get('/me/org', async (req: AuthenticatedRequest, res) => {
  const { rows: orgRows } = await pg.query(`
    SELECT o.* FROM organizations o
      JOIN profiles p ON p.org_id = o.id
     WHERE p.id = $1
  `, [req.user!.id]);
  if (orgRows.length === 0) return res.status(404).json({ error: 'no_org' });
  const org = orgRows[0];
  const { rows: members } = await pg.query(`
    SELECT om.*, p.email, p.display_name
      FROM org_members om JOIN profiles p ON p.id = om.profile_id
     WHERE om.org_id = $1 AND om.removed_at IS NULL
  `, [org.id]);
  res.json({ org, members });
});

// PATCH /api/me/org — owner can rename
apiRouter.patch('/me/org', async (req: AuthenticatedRequest, res) => {
  // Verify caller is owner
  const { rows } = await pg.query(`
    SELECT 1 FROM org_members om JOIN profiles p ON p.org_id = om.org_id
     WHERE p.id = $1 AND om.profile_id = $1 AND om.role = 'owner'
  `, [req.user!.id]);
  if (rows.length === 0) return res.status(403).json({ error: 'not_owner' });
  const { name } = req.body;
  await pg.query(`UPDATE organizations SET name = $2, updated_at = NOW()
                  WHERE owner_profile_id = $1`, [req.user!.id, name]);
  res.status(204).end();
});
```

## 5. Acceptance criteria

| AC | Description |
|---|---|
| AC-1 | Migration M10 runs idempotently |
| AC-2 | Enterprise checkout completion auto-creates org with owner = subscriber |
| AC-3 | Org auto-name = "${owner display name}'s Crew" |
| AC-4 | Subsequent Enterprise upgrades by same user re-link sub_id, do not create duplicate org |
| AC-5 | Owner profile has `org_id` set to new org |
| AC-6 | `org_members` row created with role='owner' |
| AC-7 | Enterprise subscription expiry NULLs `subscription_id` but org persists |
| AC-8 | GET /api/me/org returns org + members for any member |

| AC-10 | Removed members (`removed_at IS NOT NULL`) excluded from members list |

## 7. Edge cases

| Case | Behavior |
|---|---|
| User owns 2 orgs (rare; manual admin action) | profile.org_id holds primary; both orgs accessible via separate query |
| Owner downgrades from Enterprise → Advanced | Org persists; sub_id NULL; F10.2 blocks new invites |
| Member removed by owner | `removed_at = NOW()`; soft delete; member loses crew-data access on next request |
| Owner deleted (account deletion flow) | ON DELETE CASCADE on org_members removes their row; ownership must transfer manually (admin task) — flag in PR notes |
