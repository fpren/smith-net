# F11.1 — Audit log to DB + retention enforcement cron

| Field | Value |
|---|---|

---

## 1. Problem

`auditLog.ts` writes to a file. Not queryable. Retention policies declared in code but not enforced. Tamper detection (per-entry SHA256 checksum) computed but never verified. Compliance posture incomplete.

## 2. Goal

After this PRD: every audit event is written to a DB table; retention policies enforced by daily cron; checksum verifier runs weekly; admin endpoint can query.

## 3. Non-goals

- Migrating historical file-based logs (archive separately)
- Building admin search UI (CLI / SQL only v1)
- SIEM integration (out of scope v1)
- Per-tenant retention overrides (global policies only)

## 4. Design

### 4.1 Migration M8

```sql
-- 015_create_audit_log_table.sql
BEGIN;

CREATE TABLE IF NOT EXISTS audit_log (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  occurred_at BIGINT NOT NULL,           -- epoch ms
  action TEXT NOT NULL,
  actor_id TEXT NOT NULL,                -- user id or 'system'
  target_id TEXT,
  metadata JSONB NOT NULL DEFAULT '{}',
  ip TEXT,
  user_agent TEXT,
  checksum TEXT NOT NULL,                -- SHA256 over the entry fields
  archived BOOLEAN NOT NULL DEFAULT false,
  retention_class TEXT NOT NULL          -- 'auth' | 'messaging' | 'channel' | 'admin' | 'security'
);

CREATE INDEX IF NOT EXISTS idx_audit_log_action_time ON audit_log(action, occurred_at DESC);
CREATE INDEX IF NOT EXISTS idx_audit_log_actor_time ON audit_log(actor_id, occurred_at DESC);
CREATE INDEX IF NOT EXISTS idx_audit_log_retention ON audit_log(retention_class, occurred_at)
  WHERE archived = false;

-- Append-only DB enforcement: trigger that prevents UPDATE/DELETE on rows older than 1h
CREATE OR REPLACE FUNCTION audit_log_immutable() RETURNS trigger AS $$
BEGIN
  RAISE EXCEPTION 'audit_log is append-only';
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER audit_log_no_update BEFORE UPDATE ON audit_log
  FOR EACH ROW EXECUTE FUNCTION audit_log_immutable();
CREATE TRIGGER audit_log_no_delete BEFORE DELETE ON audit_log
  FOR EACH ROW EXECUTE FUNCTION audit_log_immutable();

COMMIT;
```

(Retention cron uses TRUNCATE-equivalent via a separate `audit_log_archive` table — see §4.4.)

### 4.2 Modify auditLog.ts to dual-write then DB-only

```typescript
// backend/src/auditLog.ts
import crypto from 'crypto';
import { pg } from './db';

interface AuditEntry { /* existing */ }

export const auditLog = {
  async log(action: AuditAction, actorId: string, metadata: any = {}, target?: string, req?: Request) {
    const occurredAt = Date.now();
    const entry: AuditEntry = {
      id: uuidv4(),
      timestamp: occurredAt,
      action,
      actorId,
      targetId: target,
      metadata,
      ip: req?.ip,
      userAgent: req?.get('user-agent'),
      checksum: '',
    };
    entry.checksum = computeChecksum(entry);

    // DB write (canonical)
    await pg.query(`
      INSERT INTO audit_log (id, occurred_at, action, actor_id, target_id, metadata, ip, user_agent, checksum, retention_class)
      VALUES ($1, $2, $3, $4, $5, $6::jsonb, $7, $8, $9, $10)
    `, [entry.id, occurredAt, action, actorId, target ?? null, JSON.stringify(metadata),
        entry.ip ?? null, entry.userAgent ?? null, entry.checksum,
        retentionClassFor(action)]);

    // File write (legacy — keep for one release cycle, then remove)
    if (process.env.AUDIT_FILE_ENABLED === 'true') {
      fs.appendFileSync(LOG_FILE, JSON.stringify(entry) + '\n');
    }
  },
};

function computeChecksum(entry: AuditEntry): string {
  const canonical = JSON.stringify({
    id: entry.id, timestamp: entry.timestamp, action: entry.action,
    actorId: entry.actorId, targetId: entry.targetId, metadata: entry.metadata,
  });
  return crypto.createHash('sha256').update(canonical).digest('hex');
}

function retentionClassFor(action: AuditAction): string {
  if (action.startsWith('user.') || action === 'token.refresh') return 'auth';
  if (action.startsWith('message.')) return 'messaging';
  if (action.startsWith('channel.')) return 'channel';
  if (action.startsWith('admin.') || action.startsWith('config.') || action.startsWith('data.')) return 'admin';
  if (action.startsWith('security.')) return 'security';
  return 'admin'; // default
}
```

### 4.4 Retention enforcement cron (daily at 02:00)

```typescript
// backend/src/jobs/auditRetentionEnforcer.ts
export async function enforceRetention() {
  for (const [cls, days] of Object.entries(RETENTION_POLICIES)) {
    const cutoff = Date.now() - days * 86_400_000;

    // Move old rows to archive (if compliance class) OR truncate
    if (cls === 'admin' || cls === 'security') {
      // Compliance: never delete; archive in compressed table after retention window for cold storage
      // For v1: just leave them; cold-storage migration in post-launch
      continue;
    }

    // Non-compliance classes: delete via privileged path (bypass append-only trigger)
    // We use a PL/pgSQL function with SECURITY DEFINER to allow deletion
    await pg.query(`
      SELECT delete_old_audit_entries($1, $2)
    `, [cls, cutoff]);
  }
}

cron.schedule('0 2 * * *', enforceRetention); // daily at 02:00 server time
```

```sql
-- 015b: privileged delete function
CREATE OR REPLACE FUNCTION delete_old_audit_entries(p_class TEXT, p_cutoff_ms BIGINT)
RETURNS INTEGER AS $$
DECLARE
  v_count INTEGER;
BEGIN
  -- Temporarily bypass triggers via session_replication_role
  SET LOCAL session_replication_role = replica;
  DELETE FROM audit_log WHERE retention_class = p_class AND occurred_at < p_cutoff_ms;
  GET DIAGNOSTICS v_count = ROW_COUNT;
  RETURN v_count;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;
```

### 4.5 Checksum verifier cron (weekly)

```typescript
// backend/src/jobs/auditChecksumVerifier.ts
export async function verifyChecksums() {
  let mismatchCount = 0;
  const { rows } = await pg.query(`
    SELECT id, occurred_at, action, actor_id, target_id, metadata, checksum
      FROM audit_log
     ORDER BY occurred_at ASC
     LIMIT 10000
  `);
  for (const row of rows) {
    const expected = computeChecksum({
      id: row.id, timestamp: Number(row.occurred_at), action: row.action,
      actorId: row.actor_id, targetId: row.target_id, metadata: row.metadata,
    });
    if (expected !== row.checksum) {
      mismatchCount++;
      console.error('[audit-tamper]', row.id, 'expected', expected, 'got', row.checksum);
      // Self-emit a SECURITY_ALERT (but we cannot tamper with this audit entry itself)
      await auditLog.log(AuditAction.SECURITY_ALERT, 'system', {
        reason: 'audit_tamper_detected', target_audit_id: row.id,
      });
    }
  }
  if (mismatchCount > 0) {
    // Alert ops out-of-band
    console.warn('[audit-tamper] total mismatches this run:', mismatchCount);
  }
}

cron.schedule('0 3 * * 0', verifyChecksums); // weekly at 03:00 Sunday
```

### 4.6 Admin query endpoint

```typescript
// GET /api/admin/audit?action=...&actor=...&since=...&limit=100
adminRouter.get('/audit', requireRole(UserRole.ADMIN), async (req, res) => {
  const { action, actor, since, limit = 100 } = req.query;
  const conditions: string[] = [];
  const params: any[] = [];
  if (action) { conditions.push(`action = $${params.length + 1}`); params.push(action); }
  if (actor) { conditions.push(`actor_id = $${params.length + 1}`); params.push(actor); }
  if (since) { conditions.push(`occurred_at >= $${params.length + 1}`); params.push(Number(since)); }
  const where = conditions.length ? `WHERE ${conditions.join(' AND ')}` : '';
  const { rows } = await pg.query(
    `SELECT * FROM audit_log ${where} ORDER BY occurred_at DESC LIMIT $${params.length + 1}`,
    [...params, Math.min(Number(limit), 1000)]
  );
  res.json({ rows });
});
```

## 5. Acceptance criteria

| AC | Description |
|---|---|
| AC-1 | Migration creates audit_log table with append-only triggers |
| AC-2 | Every audit.log() call inserts to DB |
| AC-3 | Dual-write to file enabled only when AUDIT_FILE_ENABLED env var set (default off after release window) |
| AC-4 | UPDATE / DELETE on audit_log raises exception via trigger |
| AC-5 | Retention cron daily deletes entries past cutoff for non-compliance classes |
| AC-6 | Compliance classes (admin, security) NEVER deleted |
| AC-7 | Checksum verifier finds tampered rows; emits SECURITY_ALERT entry |
| AC-8 | Admin GET /api/admin/audit returns query results, capped at 1000 rows |
| AC-9 | Non-admin GET /api/admin/audit → 403 |
| AC-10 | INSERT performance: < 5ms p95 (must not slow down auth flows) |
| AC-11 | Audit table grows linearly; partitioning deferred until > 10M rows |

## 6. BDD scenarios

```gherkin
Scenario: Login event written to audit_log
  When user logs in successfully
  Then a row exists in audit_log with action='user.login' and actor_id=userId
  And the checksum is computed correctly

Scenario: Update on audit row blocked by trigger
  Given an existing audit row
  When UPDATE audit_log SET action='hacked' WHERE id=$1 is attempted
  Then the operation fails with "audit_log is append-only"

Scenario: Retention cron deletes 30+ day messaging events
  Given audit rows from 31 days ago in retention_class='messaging'
  When enforceRetention runs
  Then those rows are deleted via delete_old_audit_entries()
  And rows from 29 days ago remain

Scenario: Compliance class never deleted
  Given audit rows from 5 years ago in retention_class='security'
  When enforceRetention runs
  Then those rows remain (compliance window 7 years)

Scenario: Checksum tampering detected
  Given an audit row whose metadata was directly mutated (out-of-band)
  When checksum verifier runs
  Then the row is identified
  And a new SECURITY_ALERT audit entry created
  And [audit-tamper] log emitted

Scenario: Admin queries audit log
  Given admin user
  When GET /api/admin/audit?action=user.login&limit=10
  Then 10 most recent user.login events returned
```

## 7. Edge cases

| Case | Behavior |
|---|---|
| DB write fails during audit | Backstop: still write to file (failsafe); alert ops |
| Trigger bypassed via direct DB access | Risk acknowledged; mitigated via DB user permissions (only superuser can SET session_replication_role) |
| Verifier finds many mismatches | Likely a bug in canonical-JSON — pause cron, investigate before alarming |
| Audit log grows huge | LIMIT 10k per verifier run; multiple runs to cycle through; partitioning when > 10M rows |
