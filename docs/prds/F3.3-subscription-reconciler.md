# F3.3 — Subscription state reconciler + provider sync cron

| Field | Value |
|---|---|
| Pitch | 3 — Stripe + Play Billing |
| Cycle | 2 |
| Appetite | 3 days |
| Owner | backend |
| Dependencies | F3.1, F3.2 |
| Closes blocker | (no specific Bxx — operational backstop) |

---

## 1. Problem

Webhooks (Stripe + Play RTDN) can drop, lag, or arrive out-of-order. Without a reconciler, our `subscriptions` table can drift from provider truth. A user's tier might be wrong for hours/days.

## 2. Goal

After this PRD: an hourly cron asks each provider what the truth is for every active subscription and reconciles. Drift detected within 1 hour. Operational confidence to scale beyond manual monitoring.

## 3. Non-goals

- Real-time sync (webhooks already do that — this is fallback)
- Bulk imports / migrations (one-time data work, separate)
- Customer service tooling (admin queries on top — out of scope)

## 4. Design

### 4.1 Cron job

```typescript
// backend/src/jobs/subscriptionReconciler.ts
import { pg } from '../db';
import { stripe } from '../services/stripeService';
import { playDeveloperApi } from '../services/playBillingService';
import { emit } from '../services/telemetry';

export async function reconcileAll() {
  const { rows: subs } = await pg.query(
    `SELECT id, profile_id, provider, provider_subscription_id, status, tier
       FROM subscriptions
      WHERE status IN ('trialing', 'active', 'past_due')
      ORDER BY updated_at ASC
      LIMIT 500`
  );

  for (const sub of subs) {
    try {
      if (sub.provider === 'stripe') await reconcileStripe(sub);
      if (sub.provider === 'play_billing') await reconcilePlay(sub);
    } catch (e) {
      console.error('[reconciler] failed for', sub.id, e);
      // continue with next; don't break the loop
    }
  }
}

async function reconcileStripe(sub: any) {
  const remote = await stripe.subscriptions.retrieve(sub.provider_subscription_id);
  if (remote.status !== sub.status) {
    await pg.query(`
      UPDATE subscriptions
         SET status=$2, current_period_end=to_timestamp($3),
             cancel_at_period_end=$4, updated_at=NOW()
       WHERE id=$1
    `, [sub.id, remote.status, remote.current_period_end, remote.cancel_at_period_end]);
    console.warn('[reconciler] stripe drift fixed', sub.id, sub.status, '->', remote.status);

    // If now expired, profile.tier downgrade is handled by F7.1 trial-expirer (which also handles paid expirations)
  }
}

async function reconcilePlay(sub: any) {
  // sub.provider_subscription_id IS the purchaseToken
  const remote = await playDeveloperApi.purchases.subscriptions.get({
    packageName: process.env.PLAY_PACKAGE_NAME!,
    subscriptionId: deriveSubIdFromTier(sub.tier),  // need to track product_id; add column if missing
    token: sub.provider_subscription_id,
  });

  const remoteStatus = derivePlayStatus(remote.data);
  if (remoteStatus !== sub.status) {
    await pg.query(`
      UPDATE subscriptions
         SET status=$2, current_period_end=to_timestamp($3/1000.0), updated_at=NOW()
       WHERE id=$1
    `, [sub.id, remoteStatus, Number(remote.data.expiryTimeMillis)]);
    console.warn('[reconciler] play drift fixed', sub.id, sub.status, '->', remoteStatus);
  }
}

function derivePlayStatus(data: any): string {
  if (data.cancelReason !== undefined) return 'canceled';
  if (Date.now() > Number(data.expiryTimeMillis)) return 'expired';
  if (data.paymentState === 0) return 'past_due';
  return 'active';
}
```

### 4.2 Schedule

Register in `server.ts`:

```typescript
import cron from 'node-cron';
import { reconcileAll } from './jobs/subscriptionReconciler';
cron.schedule('15 * * * *', reconcileAll); // every hour at :15
```

(15 past the hour to avoid colliding with cap-reset crons that would run at :00.)

### 4.3 Drift alerts

If `[reconciler]` log emits `drift fixed` more than 10 times in an hour, alert ops — webhook reliability problem.

### 4.4 Schema addition (small)

```sql
-- 009_add_product_id_to_subscriptions.sql
ALTER TABLE subscriptions
  ADD COLUMN IF NOT EXISTS provider_product_id TEXT;
```

This stores `sub_solo_monthly` etc. for Play (since reconcile needs the productId, not just the token). Backfill via a one-time script that derives from `(tier, cadence)`.

## 5. Acceptance criteria

| AC | Description | Verification |
|---|---|---|
| AC-1 | Cron runs hourly at :15 | Schedule check |
| AC-2 | For each active/trialing/past_due subscription, provider is queried | Log assertion |
| AC-3 | If remote.status differs from local, local is updated | Drift test |
| AC-4 | Per-subscription failure does not break the loop | Failure injection |
| AC-5 | Drift fix logs `[reconciler] {provider} drift fixed {sub.id} {old} -> {new}` | Log assertion |
| AC-6 | More than 10 drift-fix logs / hour triggers ops alert | Alert config |
| AC-7 | Migration adds `provider_product_id` column with backfill | Migration test |
| AC-8 | Reconciler limited to 500 subs per run; next run picks up rest via ORDER BY updated_at ASC | Pagination test |

## 6. BDD scenarios

```gherkin
Feature: Subscription reconciler catches webhook drift

Scenario: Stripe subscription canceled but webhook missed
  Given a local subscription with status="active" and provider="stripe"
  And the actual Stripe subscription is canceled
  When the reconciler runs
  Then the local row updates to status="canceled"
  And a [reconciler] drift fixed log line is emitted

Scenario: Play purchase expired but RTDN missed
  Given a local subscription with status="active" and provider="play_billing"
  And Google Play API reports expiryTimeMillis in the past
  When the reconciler runs
  Then the local status becomes "expired"

Scenario: Single sub failure doesn't break loop
  Given 100 subscriptions to reconcile
  And one of them throws an error during query
  Then the reconciler logs the error
  And continues with the remaining 99

Scenario: No drift, no update
  Given a local subscription that matches provider state
  When reconciler runs
  Then no UPDATE is issued
  And no [reconciler] drift log fires
```

## 7. Edge cases

| Case | Behavior |
|---|---|
| Provider rate limit hit | Cron handles gracefully; next run picks up |
| Stripe customer deleted out-of-band | Reconciler returns 404; mark subscription expired |
| Play purchase token expires (lifetime ~30 days for non-renewing) | Reconciler treats as expired; F7.1 downgrades tier |
| Reconciler runs while webhook is processing same sub | Last write wins; both should converge to same value |
| Production has 10k active subs | Loop limit 500/run; takes 20 runs (~20h) to fully cycle — acceptable; raise limit if needed |

## 9. Risk

| Risk | Mitigation |
|---|---|
| Reconciler's API calls cost $$ at scale | Limit 500/run; staggered hourly; well within Stripe + Play free tiers for reasonable subscriber counts |
| Reconciler floods logs | Log only on drift (no log on no-change) |
| Reconciler crashes mid-run | Next run resumes via ORDER BY updated_at ASC |
