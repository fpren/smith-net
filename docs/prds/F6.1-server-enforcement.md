# F6.1 — Server enforcement middleware + tier_gate_exceeded contract

| Field | Value |
|---|---|
| Pitch | 6 — Server enforcement |
| Cycle | 2 |
| Appetite | 4 days |
| Owner | backend |
| Dependencies | F2.1, F2.2 (resolver + requireTier), F5.2 (telemetry sink) |
| Closes blocker | B5 |

---

## 1. Problem

F2.2's `requireTier(min)` enforces tier minimums but doesn't enforce **caps within a tier** (active jobs, PDF sends per month). Without these middlewares actually wired to the cap-bearing endpoints (POST /api/jobs, POST /api/invoices/:id/send), the client UI can be bypassed. Money mechanics fail.

## 2. Goal

After this PRD:
- A reusable `requireCap` middleware factory enforces server-authoritative caps per tier
- POST /api/jobs refuses 2nd active job for Open with structured 403
- POST /api/invoices/:id/send refuses 6th PDF this month for Open with structured 403
- Telemetry fires automatically on every cap-hit (server-side, can't be bypassed)
- 403 response shape matches `TECHNICAL-SPEC.md §3.4` and `API-SPEC.md §19`

## 3. Non-goals

- Rate limiting beyond per-tier caps (existing express-rate-limit unchanged)
- Soft warnings before cap hit (per UX Principle 2: no proactive nag)
- The client overlay UI (F4.x)
- Trial mechanics (F7.1)

## 4. Design

### 4.1 Middleware factory

```typescript
// backend/src/middleware/requireCap.ts
import { Request, Response, NextFunction } from 'express';
import { AuthenticatedRequest } from '../auth';
import { resolveTier, Entitlements } from '../services/tierResolver';
import { emit as emitTelemetry } from '../services/telemetry';
import { Tier } from '../types/tier';

export type CapName = 'activeJobs' | 'pdfSendsPerMonth';

interface RequireCapOptions {
  capName: CapName;
  gateId: string;          // 'active_job_cap' | 'pdf_send_cap'
  getCurrent: (req: AuthenticatedRequest) => Promise<number>;
  targetTier: Tier;        // tier needed to bypass cap
}

export function requireCap(opts: RequireCapOptions) {
  return async (req: AuthenticatedRequest, res: Response, next: NextFunction) => {
    const profileId = req.user!.id;
    const entitlements = await resolveTier(profileId);
    const limit = entitlements.caps[opts.capName];

    if (limit === 'unlimited') return next();

    const current = await opts.getCurrent(req);
    if (current >= limit) {
      // Telemetry — server-authoritative
      await emitTelemetry(`gate_hit.${opts.gateId}`, profileId, entitlements.tier, {
        limit, current, attempted_at: new Date().toISOString(),
      });
      return res.status(403).json({
        error: `Tier cap reached: ${opts.gateId}`,
        code: 'tier_gate_exceeded',
        gate_id: opts.gateId,
        current_tier: entitlements.tier,
        limit,
        current,
        details: { target_tier: opts.targetTier },
      });
    }
    next();
  };
}
```

### 4.2 Wire to POST /api/jobs

```typescript
// backend/src/api.ts
import { requireCap } from './middleware/requireCap';

const activeJobsCap = requireCap({
  capName: 'activeJobs',
  gateId: 'active_job_cap',
  targetTier: 'solo',
  getCurrent: async (req) => {
    const { rows } = await pg.query(
      `SELECT COUNT(*) AS cnt FROM jobs
        WHERE created_by = $1 AND status NOT IN ('done', 'archived')`,
      [req.user!.id]
    );
    return Number(rows[0].cnt);
  },
});

apiRouter.post('/jobs', activeJobsCap, validateBody(CreateJobBody), async (req, res) => {
  // existing job creation logic
});
```

### 4.3 Wire to POST /api/invoices/:id/send

```typescript
const pdfSendsCap = requireCap({
  capName: 'pdfSendsPerMonth',
  gateId: 'pdf_send_cap',
  targetTier: 'solo',
  getCurrent: async (req) => {
    const { rows } = await pg.query(
      `SELECT pdf_sends_this_month AS cnt FROM profiles WHERE id = $1`,
      [req.user!.id]
    );
    return Number(rows[0].cnt);
  },
});

apiRouter.post('/invoices/:id/send', pdfSendsCap, async (req, res) => {
  // existing send logic
  // After successful send, increment counter:
  await pg.query(
    `UPDATE profiles SET pdf_sends_this_month = pdf_sends_this_month + 1 WHERE id = $1`,
    [req.user!.id]
  );
});
```

### 4.4 Monthly cap reset cron

```typescript
// backend/src/jobs/resetMonthlyCounters.ts
// Runs at 00:01 on day 1 of each month
export async function resetMonthlyCounters() {
  const monthKey = new Date().toISOString().slice(0, 7); // 'YYYY-MM'
  await pg.query(`
    UPDATE profiles
       SET pdf_sends_this_month = 0,
           pdf_sends_month_key = $1
     WHERE pdf_sends_month_key != $1
  `, [monthKey]);
  console.info('[monthly-reset] reset pdf_sends_this_month for all users');
}

// schedule in server.ts
cron.schedule('1 0 1 * *', resetMonthlyCounters);
```

This handles users who were active in the prior month but not yet today — `pdf_sends_month_key` mismatch triggers reset on next read too (defense-in-depth via app-level check).

### 4.5 App-level fallback for month rollover

```typescript
// when reading the counter:
async function getCurrentPdfSends(profileId: string): Promise<number> {
  const monthKey = new Date().toISOString().slice(0, 7);
  const { rows } = await pg.query(
    `UPDATE profiles
       SET pdf_sends_this_month = CASE WHEN pdf_sends_month_key = $2 THEN pdf_sends_this_month ELSE 0 END,
           pdf_sends_month_key  = $2
     WHERE id = $1
     RETURNING pdf_sends_this_month`,
    [profileId, monthKey]
  );
  return Number(rows[0].pdf_sends_this_month);
}
```

(If cron runs reliably, this is a no-op. If cron is delayed, app self-heals.)

  When POST /api/jobs

  And pdf_sends_month_key = "2026-05"

  When POST /api/synthesize with valid body

## 7. Edge cases

| Case | Behavior |
|---|---|
| Cap counter check race vs increment | Use single transactional `SELECT ... FOR UPDATE` then UPDATE with check |
| User upgrades to Solo mid-attempt | Next request reads new entitlements; cap removed |
| User's tier_expires_at passes mid-request | Resolver returns Open caps; refuse with 403 |
| Manual DB UPDATE bypasses counter | Reconciler doesn't re-derive from send_log; defense-in-depth: separate audit query |
| Job archived/deleted does not count toward active | `WHERE status NOT IN ('done','archived')` filter; deleted = `is_deleted=true` separately |

## 10. Risk

| Risk | Mitigation |
|---|---|
| Race between cap check and counter increment | Atomic INSERT with `WHERE` clause checking limit; or transactional FOR UPDATE; tested under load |
| Counter drift over months | Audit script reconciles `pdf_sends_this_month` against actual sends in current month |
| Cron timing issues at month boundary | App-level fallback handles |
