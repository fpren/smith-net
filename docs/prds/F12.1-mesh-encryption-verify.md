## 1. Problem

`SECURITY.md` and `NFRS.md NFR-S3` claim mesh payloads are encrypted (AES-GCM) — but this needs to be **verified in code** and gaps fixed. Plus: no per-message signing; no replay protection.

## 2. Goal

After this PRD:
- Confirmed (or implemented) AES-GCM encryption on all mesh payloads
- HMAC-SHA256 signing per message; receiver verifies
- Replay protection: monotonic timestamp + messageId dedup within 5-min window
- Penetration tests pass: replay attempt fails, tampered payload rejected

## 3. Non-goals

- Forward secrecy (per-pair static keys are fine v1)
- Encrypted-at-rest local mesh storage (SQLite default; future)
- Re-architecting MeshService

### 4.2 Encryption (if missing or weak)

```kotlin
// android/.../service/MeshCrypto.kt
object MeshCrypto {
    private const val ALGORITHM = "AES/GCM/NoPadding"
    private const val KEY_SIZE_BITS = 256
    private const val IV_SIZE_BYTES = 12
    private const val TAG_SIZE_BITS = 128

    fun encrypt(plaintext: ByteArray, key: SecretKey): ByteArray {
        val iv = ByteArray(IV_SIZE_BYTES).also { SecureRandom().nextBytes(it) }
        val cipher = Cipher.getInstance(ALGORITHM)
        cipher.init(Cipher.ENCRYPT_MODE, key, GCMParameterSpec(TAG_SIZE_BITS, iv))
        val ciphertext = cipher.doFinal(plaintext)
        return iv + ciphertext  // prepend IV for receiver
    }

    fun decrypt(payload: ByteArray, key: SecretKey): ByteArray? {
        if (payload.size < IV_SIZE_BYTES + TAG_SIZE_BITS / 8) return null
        val iv = payload.copyOfRange(0, IV_SIZE_BYTES)
        val ct = payload.copyOfRange(IV_SIZE_BYTES, payload.size)
        val cipher = Cipher.getInstance(ALGORITHM)
        cipher.init(Cipher.DECRYPT_MODE, key, GCMParameterSpec(TAG_SIZE_BITS, iv))
        return try { cipher.doFinal(ct) } catch (e: AEADBadTagException) { null }
    }

    fun keyFromPairing(sharedSecret: ByteArray): SecretKey =
        SecretKeySpec(sharedSecret.copyOf(32), "AES")
}
```

Pairing key established via BLE bond — already exists in `MeshService.pair()`. Extract bond shared secret as input.

### 4.3 Per-message signing (HMAC-SHA256)

```kotlin
// android/.../service/MeshSigner.kt
object MeshSigner {
    fun sign(payload: ByteArray, key: SecretKey): ByteArray {
        val mac = Mac.getInstance("HmacSHA256")
        mac.init(key)
        return mac.doFinal(payload)
    }
    fun verify(payload: ByteArray, signature: ByteArray, key: SecretKey): Boolean {
        val expected = sign(payload, key)
        return expected.contentEquals(signature)  // constant-time compare in production
    }
}
```

### 4.4 Wire frame format

```
[4 bytes msg version][16 bytes UUID messageId][8 bytes timestamp][N bytes encrypted-and-signed payload][32 bytes HMAC]
```

Layered: encrypt then sign (encrypt-then-MAC pattern). MAC computed over (version || messageId || timestamp || ciphertext).

### 4.5 Replay protection

```kotlin
// android/.../service/ReplayDefender.kt
object ReplayDefender {
    private val recentMessageIds = ConcurrentLinkedHashMap.Builder<String, Long>()
        .maximumWeightedCapacity(10_000)
        .build()
    private const val WINDOW_MS = 5 * 60 * 1000L

    /** Returns true if message accepted; false if duplicate/replay/out-of-window. */
    fun accept(messageId: String, timestampMs: Long): Boolean {
        val now = System.currentTimeMillis()
        if (Math.abs(now - timestampMs) > WINDOW_MS) return false  // out of window
        if (recentMessageIds.containsKey(messageId)) return false  // duplicate
        recentMessageIds[messageId] = now
        // periodic eviction
        if (Math.random() < 0.001) {
            recentMessageIds.entries.removeIf { now - it.value > WINDOW_MS }
        }
        return true
    }
}
```

### 4.6 Wire into MeshService

```kotlin
// MeshService.kt — broadcast path
fun broadcastMessage(message: Message) {
    val plaintext = message.toJsonBytes()
    val ciphertext = MeshCrypto.encrypt(plaintext, sessionKey)
    val frame = buildFrame(VERSION, message.id, message.timestamp, ciphertext)
    val signature = MeshSigner.sign(frame, sessionKey)
    transmitOverBle(frame + signature)
}

// MeshService.kt — receive path
fun onMessageReceived(rawBytes: ByteArray) {
    if (rawBytes.size < FRAME_HEADER_SIZE + HMAC_SIZE) { logSecurityAlert("too short"); return }
    val frame = rawBytes.copyOfRange(0, rawBytes.size - HMAC_SIZE)
    val signature = rawBytes.copyOfRange(rawBytes.size - HMAC_SIZE, rawBytes.size)
    if (!MeshSigner.verify(frame, signature, sessionKey)) { logSecurityAlert("bad signature"); return }
    val (version, messageId, timestamp, ciphertext) = parseFrame(frame)
    if (!ReplayDefender.accept(messageId, timestamp)) { logSecurityAlert("replay or out-of-window"); return }
    val plaintext = MeshCrypto.decrypt(ciphertext, sessionKey) ?: run { logSecurityAlert("decrypt fail"); return }
    val message = Message.fromJsonBytes(plaintext)
    deliver(message)
}
```

## 5. Acceptance criteria

| AC | Description |
|---|---|
| AC-1 | Audit identifies whether existing encryption present (yes/no/partial) |
| AC-2 | If absent or weak, AES-GCM-256 with random 96-bit IV implemented |
| AC-3 | Every mesh message HMAC-SHA256 signed |
| AC-4 | Frame format: version + messageId + timestamp + ciphertext + HMAC |
| AC-5 | Replay defender rejects same messageId twice within 5min |
| AC-6 | Replay defender rejects timestamp older / newer than 5min from now |
| AC-7 | Tampered payloads rejected with `[security-alert] bad signature` log |
| AC-8 | Decrypt failure logged with `[security-alert] decrypt fail` |
| AC-9 | All security-alert logs increment `SECURITY.SECURITY_ALERT` audit |
| AC-10 | Mesh latency overhead < 50ms per message (encryption + signing budget) |
| AC-11 | SECURITY.md §11 updated with current encryption details + key management |
| AC-12 | Security gap S3, S12, G8 closed in DEV-READINESS / SECURITY |

## 7. Edge cases

| Case | Behavior |
|---|---|
| Encryption already present in code | Audit confirms; document; skip implementation; still add signing + replay |
| Key derivation fails (no BLE bond) | Refuse to send/receive; log; force re-pairing |
| Clock skew between devices | 5-min window covers normal NTP drift |
| Receiver storage limit (10k recent IDs) | LRU eviction; oldest IDs may be re-accepted after eviction (low risk in 5min window) |
| Pairing key compromised | Re-pair via BLE; forces new shared secret; old messages rejected (signature fails on new key) |
